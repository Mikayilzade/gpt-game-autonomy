# G8C02 — Locksmith's Margin — FINALIST

## Minimal primitive/state vocabulary
- key blank family;
- 5–6 discrete cut columns;
- discrete depth per column;
- irreversible `file one step deeper` verb;
- lock pin requirement per column;
- bounded tolerance interval per pin;
- optional master interval producing two valid depths;
- visible impression state: no mark / light / strong at a column;
- test result: blocked at first incompatible column or opens;
- finite authored set of locks and blanks per case.

No lock-specific exception verb is permitted. Worn locks alter tolerance width only. Master pins alter valid intervals only. A scenario that requires springs breaking, hidden wards, random jams, special picks, lock lubricant, timed dexterity, or bespoke key shapes fails the content model.

## Six mature scenarios
1. **Sibling cylinders:** three locks share four of six pin intervals. Two blanks. A key specialized to A destroys the only overlap with C; a deliberately imperfect A/B compromise plus a second C key wins.
2. **Diagnostic sacrifice:** one cheap blank can be tested deeply against an unknown member of a lock family. Filing it to chase the first lock would open that lock but erase information about which family the later two belong to. Correct play preserves it as a probe.
3. **Master split:** lock A accepts depths 2 or 4 at column 3; B accepts 3–4; C accepts 1–2. Greedy deepest-compatible filing loses C. Player must exploit the shallow master branch first.
4. **Wear bridge:** a worn service lock accepts a broad interval, making one key compatible with it and a precise cabinet lock. Exact-copying the service lock is unnecessary and strategically harmful.
5. **Order inversion:** impression from B reveals that column 5 is already too deep for B, so testing B first tells the player not to spend that blank there; a second blank is then cut for B/C. Current-lock-first specialization loses.
6. **Three-way finale:** four locks, three blanks, two master intervals and one worn cylinder. The solution requires one exact key, one deliberately under-resolved shared key, and one diagnostic key later converted after its information value is exhausted.

Scenarios 1, 3, 4 and 6 defeat `make the current key as accurate as possible`; scenarios 2 and 5 defeat `always finish the lock currently on the bench`.

## Cheapest policy attack
**P1: monotonically file toward the strongest current impression until open.** Counterexample: sibling cylinders — opening A via a deeper cut destroys A/B overlap needed under the blank count.

**P2: always preserve the shallowest possible key because deeper cuts are irreversible.** Counterexample: three-way finale — one exact deep key must be committed early because its lock's valid interval has no overlap and delaying it consumes the diagnostic blank.

No new rule is needed for either counterexample.

## ~20-minute demo
0–3 min: transparent training cylinder, one blank, learn discrete cut and impression.
3–6: second lock, first overcut shown as permanent; instant restart/undo-before-commit boundary taught.
6–10: two sibling locks / two blanks; discover one imperfect key can open both.
10–14: master interval introduced visually inside transparent cylinder; two valid depths, no terminology dump.
14–20: three-lock finale where strongest-impression greed loses and preserving compatibility wins. End on same visibly scarred key opening two different locks.

## UI-removed trailer causality
Pass. Vice, file, changing metal profile, physical insertion, pin stack movement, impression mark, refusal to cut, then same key opening a second cylinder remain understandable without HUD. A translucent cut-grid can be diegetic bench tooling rather than dashboard authority.

## ~30-situation production model
Six structural families × ~5 authored cases:
A sibling-overlap; B destructive diagnosis; C master-interval branching; D wear/tolerance bridge; E test-order/information value; F mixed multi-lock allocation.
Recombination dimensions: columns 4–6, depth range 4–6, overlap topology of valid intervals, blank count, test access order, master columns 0–2, wear width 0–1. New verbs are forbidden after the demo. Cases must be solver-validated for at least one solution and for rejection of the obvious greedy policy when labeled mature.

## Current analogue boundary
Safecracking/lockpicking simulators already expose mechanical lock internals and real techniques. Boundary: **this is not picking a lock; the persistent object being reasoned about is a destructively edited key whose partial compatibility across several locks is intentionally valuable.** Search this run did not surface a current Steam product owning that exact multi-lock destructive-key grammar.

## Implementation-risk attack — readable tolerance/destructive correction
Risk is false precision: a realistic continuous key profile would make success feel arbitrary. Therefore authority must be discrete. Each cut snaps to a finite depth. Each lock exposes pin movement physically; after a failed test the first blocking column is visibly marked. Tolerance is a finite accepted set/interval, never floating-point fuzz. Filing animation may be continuous but commits exactly one depth step. If this abstraction looks toy-like rather than tactile, presentation fails but rules remain coherent.

## Structural-isomorphism attack
Not cargo transport (#001), document/reality bureaucracy (#002), property transfer (#003), hidden audio inference (#004), conserved network budget (#005), adjacency rewiring (#006), or observation-form commit (#007). Irreversible state editing exists as a generic design pattern but the authority grammar — one persistent physical artifact satisfying overlapping tolerance sets — is new to portfolio.

## Vertical-slice kill gates
Build only 3 locks / 2 blanks / 5 columns / 5 depths.
KILL if any occurs in 8 fresh-player sessions:
- >=3 players cannot explain why a specific cut destroyed later compatibility after replay/feedback;
- >=6 solve by strongest-impression greed with no deliberate preservation decision;
- median time spent reading numeric/UI state exceeds time watching/manipulating key+lock physical state;
- the same optimal action sequence survives two materially different lock sets;
- a continuous/freeform cutting implementation is required to make the fantasy satisfying.

**RUN-2 VERDICT: FINALIST #1.** Strongest compact grammar, strongest tactile causality, lowest bespoke-content dependency.

# G8C04 — Window Garden — FINALIST

## Minimal primitive/state vocabulary
- facade cell grid;
- authored sun lane per day/epoch;
- shutter with 2–3 discrete orientations;
- plant as directed growth-node graph;
- active tip;
- deterministic next-node candidate chosen by light/support rule;
- prune branch verb;
- trellis/support cell;
- shade/occlusion state;
- vent/pollinator passage cell;
- exact next-day ghost preview.

Species may change only a small parameter tuple: preferred light band, branch pattern, climb/support preference, flowering epoch. No hidden random growth.

## Six mature scenarios
1. **Shade debt:** grow a fast vine today to shade a seedling tomorrow, then prune the same canopy before it starves a flowering plant on day three.
2. **Support fork:** two equal-light growth candidates; shutter orientation makes one touch a trellis, changing the next deterministic branch direction and preserving a vent.
3. **Bridge then remove:** a temporary branch must reach a pollinator perch, enable one pollination epoch, then be pruned so later sun reaches a lower plant.
4. **Mutual interference:** plant A's useful climb shades B; B must first grow a support-bearing branch that later redirects A, reversing apparent priority.
5. **Window reservation:** maximizing today's growth occupies a facade cell needed by a slower plant's only support path two days later. Correct play intentionally leaves light unused.
6. **Three-day finale:** shutters cannot illuminate both tips simultaneously; prune timing, one temporary shade canopy, and a trellis fork must be sequenced so two plants flower while vent remains clear.

Scenarios 1, 3, 5, 6 defeat maximize-light/maximize-growth. Scenarios 2 and 4 defeat always-prioritize-the-most-constrained-current-tip.

## Cheapest policy attack
**P1 maximize illuminated active tips each day.** Counterexample: Window Reservation; extra growth permanently occupies the future support cell.

**P2 prune any branch that currently blocks an objective.** Counterexample: Bridge Then Remove; the blocking branch is temporarily required for pollinator access before removal.

## ~20-minute demo
0–4: one vine, one shutter, exact tomorrow ghost.
4–7: trellis redirects deterministic growth.
7–10: pruning removes a future branch and updates ghost immediately.
10–14: first shade interaction: more growth can be harmful.
14–20: two plants; temporary canopy helps then hurts; finale requires deliberate delayed prune.

## UI-removed trailer causality
Strong pass if ghost preview is rendered in-world. Sun stripe moves, shutter clicks, ghost branch changes, player prunes, day advances, plant exactly occupies ghost geometry and casts visible shade. HUD text is unnecessary.

## ~30-situation production model
Six families × ~5: light routing, support forks, temporary shade, temporary access/bridge, competing species, multi-day reservation. Recombine facade shape, sun epochs, shutter placement/orientation, trellis cells, plant start nodes, growth templates, objective cells. Hard ceiling 3 reasoning-critical plants and 4 days per normal case to protect forecastability.

## Current analogue boundary
`Prune` already owns shaping tree growth toward light; `Cloud Gardens` owns plants growing through dioramas; `Botany Manor` owns plant cultivation as environmental puzzle. Boundary must therefore be narrow and visible: **architectural shutters + exact next-cycle geometry + delayed shade/support interactions, with pruning used to schedule future geometry rather than simply guide a tree toward light.** This is a real collision risk, not a marketing footnote.

## Implementation-risk attack — deterministic growth
Authoritative growth cannot be procedural curves. Each plant is a graph of discrete candidate nodes transformed onto facade cells. Preview and resolution call the same pure function. Rendering interpolates stems between nodes after authority resolves. Occlusion uses discrete occupancy. Any species rule that cannot preview exact next state is prohibited.

## Structural-isomorphism attack
The exact future ghost superficially resembles #007 candidate preview, but authority differs: #007 commits an observed form; here player changes environment/prunes and deterministic temporal growth resolves from rules. To avoid contamination, there is no `confirm remembered form`, no choice among authored object forms, and preview itself never changes state.

## Vertical-slice kill gates
2 plants, 2 shutters, 1 trellis, 3 days.
KILL if:
- >=3/8 players see a previewed growth result differ from what they expected after advance;
- >=6/8 default to maximize light and still solve the mature slice;
- plant state requires textual species rules during decision-making after tutorial;
- branch/occlusion resolution needs continuous collision geometry;
- trailer footage without explanatory captions is mistaken primarily for decoration/cozy gardening by >=5/8 target players.

**RUN-2 VERDICT: FINALIST #2.** Exceptional visual causality and delayed consequence, but direct `Prune`/plant-puzzle comparison remains a major final-round liability.

# G8C07 — Firebreak Foreman — FINALIST, HIGH RISK

## Minimal primitive/state vocabulary
- discrete site cells/edges;
- material class with ignition delay and burn duration;
- state: intact / prepared / burning / spent;
- declared wind epoch and direction;
- spread edge rule;
- worker-access edge;
- four interventions: clear, soak(delay), open/close authored structure aperture, ignite controlled sacrifice where allowed;
- protected and expendable objectives;
- exact one-step spread preview.

No stochastic spotting, continuous fluid fire, hidden heat, physics-derived ember trajectories or arbitrary firefighter stats.

## Six mature scenarios
1. **Remote break:** hottest front is irrelevant; clear a remote strip before a declared wind turn connects it to the protected pump.
2. **Sacrificial shed:** deliberately ignite an expendable fuel shed under current wind so it is spent before the later wind epoch would carry fire through it.
3. **Access first:** obvious soak target is reachable now, but smoke/spread will cut worker exit; clear access edge first, then return.
4. **Delay chain:** soaking does not save a structure; it delays ignition exactly one step, enough for adjacent fuel to become spent and break the chain.
5. **Vent trap:** opening an authored warehouse door creates a known spread edge that burns expendable interior fuel early; keeping it closed preserves dangerous fuel until wind turns.
6. **Mixed finale:** protect two assets, accept loss of one shed, use clear + one-step soak + controlled sacrifice across two wind epochs. Maximum-line clearing fails because it strands worker access.

## Cheapest policy attack
**P1 clear the longest contiguous line between fire and objectives.** Counterexample: Remote Break; wind epoch makes a shorter oblique break authoritative.

**P2 always save every currently savable structure.** Counterexample: Sacrificial Shed; preserving it leaves fuel alive for the later wind and loses the protected pump.

## ~20-minute demo
0–4 simple cell spread + clear.
4–7 material burn duration/spent cells.
7–10 declared wind shift.
10–13 soak as exact delay, not extinguish.
13–16 worker access closure.
16–20 final chosen-sacrifice site using all four concepts; controlled ignition optional only after player has seen natural fuel exhaustion.

## UI-removed trailer causality
Conditional pass. Cell/edge authority must be visible through site geometry, wind sock, ground strip, material state and a short in-world next-spread edge glow. If the exact preview needs a tactical overlay covering the scene, fail.

## ~30-situation production model
Six families × ~5: break geometry, wind epoch, fuel exhaustion, exact delay, access preservation, chosen sacrifice. Recombine compact site layout, material map, wind sequence, intervention availability and objective values. No new fire physics per level.

## Current analogue boundary
This pass found a serious analogue: `Wildfire Swap` already describes creating firebreaks, redirecting/containing spreading fire and 120+ handcrafted puzzle levels. Larger sims also expose fire lines/backfires/wind. Boundary: **Firebreak Foreman is a compact deterministic intervention puzzle about material burn timing, worker access and intentionally consuming expendable structures across declared wind epochs — not tile swapping and not action/incident-command firefighting.** Still, store-level collision is substantial.

## Implementation-risk attack — discrete fire authority/readability
Simulation is a deterministic cellular event queue. VFX is downstream only. At each step, ignition candidates are derived from current burning cells, allowed edges, material delay and wind epoch. Preview calls the same rule. Fire particles may never cross an edge before authoritative ignition cue. Smoke may visually obscure but cannot hide decision-critical state; accessibility mode replaces smoke density with outline treatment.

## Structural-isomorphism attack
Not #005 conserved load and not #006 rewired adjacency. Opening a door toggles one authored spread edge, which risks topology resemblance; therefore door/aperture interaction must remain a minority verb and no level may be solved primarily by graph rewiring. Central grammar is temporal fuel consumption + sacrifice under changing spread direction.

## Vertical-slice kill gates
One 8–12-cell site, 2 material classes, one wind shift, clear/soak/sacrifice.
KILL if:
- >=2/8 players attribute a loss to random/hidden fire behavior after replay;
- exact preview requires abstract grid overlay for most decisions;
- longest-line clearing solves the mature slice;
- removing worker access leaves almost all strategic depth intact;
- target-player blind store test describes it as `Wildfire Swap but 3D` or generic firefighting in >=4/8 cases.

**RUN-2 VERDICT: FINALIST #3, HIGH RISK.** Best spectacle and sacrifice drama; analogue collision and authority readability are serious enough that it enters final round behind Locksmith and Window Garden.

# G8C01 — Maintenance Window — KILL

## Primitive vocabulary and six-scenario stress
A compact grammar can be written: machine phase, wear state, dependency, bypass, local heat, service lockout, two-stage task. Six scenarios are feasible: shared-bypass order; planned healthy shutdown; split service around live cycle; heat debt; bypass reservation; cascade recovery. Greedy highest-wear-first can be defeated by dependency windows and bypass conflicts.

## Why it collapses anyway
The mature decision surface is a dependency graph with timers/wear/heat, even if rendered physically. Hands-on service animation does not change the reasoning unless bespoke repair interactions are added; adding them creates exception/minigame burden. The cheap solver is earliest-deadline/critical-path scheduling with local capacity constraints. Counterexamples can defeat a single heuristic, but they do so by adding more dependency/timing parameters rather than a qualitatively richer physical grammar.

Fresh analogue research materially worsens the case: `Pressure Crew` currently pitches a maintenance foreman keeping a connected industrial plant alive through leaks, blockages, contamination, heat and pressure cascades, with specialist intervention and a short demo. Factory puzzle/automation products also occupy the industrial dependency surface. Our planned-outage emphasis is a boundary, but the store silhouette and minute-to-minute plant-cascade fantasy are no longer sufficiently protected.

**Kill gate triggered on paper:** if hands-on service can be replaced by a `service` button without changing the reasoning, kill. It can. Making service itself mechanically deep would require new repair vocabularies and break the compact-system objective.

**VERDICT: KILL.** Strong system, insufficiently distinct physical decision grammar and newly material current analogue collision.

# G8C10 — Greenhouse Night Shift — KILL

## Primitive vocabulary and six-scenario stress
Fixed aisle, gate, vent, humidity epoch, flower state, agent active window, deterministic next target, pest state. Six scenarios can be authored: dual pollinator windows; vent/flower conflict; pest isolation; visit-order cross-pollination; humidity timing; two-agent finale.

## Why it collapses anyway
To keep autonomous agents interesting, pollinators need different target preferences/windows; plants need different flowering/humidity reactions; pests need separate restrictions. The minimal vocabulary therefore grows as an exception matrix. If those differences are reduced to one uniform target rule, the game collapses into `open/close fixed gates at the correct time`, structurally close to scheduling/topology. The cheapest solver becomes finite-state route scheduling; counterexamples require adding biological predicates rather than recombining a stronger physical primitive.

Current greenhouse/butterfly imagery is also busy: 2026 `Lepidarium` sells butterfly/moth greenhouse collection and `GeneBloom` sells greenhouse breeding/tycoon fantasy. They are mechanically different, but they consume part of the visual/product-language advantage. Window Garden has the stronger plant-space visual causality while Maintenance had the stronger scheduling system; Greenhouse sits between them without winning either axis.

**Kill gates triggered on paper:** depth needs a growing biological exception taxonomy; removing agent species fiction leaves fixed-route time-window scheduling; reducing species exceptions makes the #006 topology/scheduling resemblance too strong.

**VERDICT: KILL.** Do not rescue by adding more species, pests or ecology rules.
