## 3. Enumeration / branching attack
Cheap Undo, exact footprints and <=3 clocks make brute-force experimentation inherently possible. This is acceptable; the game fails only if brute force is the *primary intended cognitive surface*.

Shipping gates from Case 12 onward:
1. human_causal_proof contains 2–6 public claims;
2. at least one claim eliminates a nontrivial class of legal early actions before simulation;
3. Chapter 4+ normally has two independent causal cuts;
4. solver report records legal first-action count and the fraction eliminated by each declared causal cut;
5. reject a case if success is mainly discovered by scanning near-identical sockets;
6. reject difficulty whose branching comes mainly from adding sockets rather than interactions;
7. explicit symmetry groups are normalized for analysis; apparent diversity created only by swapping equivalent clocks does not count.

No numeric universal threshold for “enough pruning” is frozen because topology sizes vary. Phase 11 must freeze the qualitative review contract: a reviewer must be able to state what class of actions each causal claim rules out.

## 4. Materially different winning routes — structural definition
Two winning routes are materially different only if, after removing no-op Resolves and normalizing explicitly declared symmetric clock/entity IDs, at least one is true:
- their persistent milestone partial-order DAGs differ by at least one non-commuting precedence relation;
- they use different carrier/destination roles that alter a later prerequisite;
- they neutralize an irreversible hazard through different public prerequisite structures;
- they reserve different clock roles for the final CURRENT state and this changes earlier dependencies.

Differences in animation order, equivalent socket choice, interchangeable clock ID, extra harmless Resolve, or merely higher move count do **not** create a new route family.

Cases 30 and 35 must solver-prove >=2 such route families. Other cases may have one.

## 5. Resolve/no-op attack
No-placement Resolve remains legal because carrier/accept boundaries can require it. But unchanged-layout farming is rejected when repeated Resolve advances strategically useful process milestones without a new public interaction.

Authoring validator must flag any reachable state where two consecutive no-placement Resolves under identical clock layout produce two useful persistent advances on the same process chain. Exception requires an explicit tutorial/interaction justification tag and manual review; none is expected after Chapter 1.

No-op Resolve that advances a carrier one public hop is meaningful and legal. A Resolve that changes neither persistent state nor carrier state may still be legal for CURRENT/final-objective checking, but repeated empty Resolves never improve score and should not be required by authored optimal solutions.

## 6. Late-game depth ceiling attack
<=3 clocks and <=8 sites remains sufficient if late puzzles braid three kinds of dependency rather than enlarge the board:
- irreversible prerequisite;
- boundary staging (process/carrier/accept);
- final simultaneous CURRENT reservation.

A late case should normally use 2–4 of these, not all eight semantic families. More families do not equal more depth. Any Case 31–36 needing >8 sites, >3 clocks, >2 carriers, >5 labels or >6 normal Resolves must be simplified or explicitly re-reviewed; do not raise ceilings to save a case.

## 7. Semantic clarity attack
Mandatory player-facing distinctions:
- NOW = recomputed current truth;
- DONE = persistent earned state;
- LOCKED OUT = persistent bad state;
- ARRIVED — eligible next Resolve = carrier boundary;
- final CURRENT objectives visibly remain NOW requirements after persistent goals are earned;
- Resolve with no placement is presented as “advance one Resolve boundary,” never “wait five minutes.”

Earlier-looking labels never animate reversal. If a case requires no-placement Resolve, the relevant rule card must expose why a boundary can matter (carrier hop/accept eligibility/process rule); no hidden waiting.

## 8. Controller / Deck / localization attack
At 1280x800 with maximum text size + pseudolocalization simultaneously:
- objective essentials, selected site's effective time, NOW/DONE/LOCKED OUT, selected clock label, footprint/conflict and Resolve action must remain directly visible;
- long rule prose may expand in one non-destructive overlay;
- overlay cannot hide the currently referenced site/clock without a return/focus path;
- all footprint states have shape/pattern/text reinforcement, never color alone;
- animation skip/reduced motion must still expose the same structured reason events;
- controller focus traversal must reach every legal socket and return to action rail with no trap.

Failure of this combined stress layout is a UI implementation defect, not permission to shrink text below the accessibility target.

## 9. Persistence / corruption / cloud attack
Required behavior:
- authoritative post-Resolve active state and pre-Resolve Undo Turn checkpoint are separate records;
- save during/after animation loads post-Resolve authority and may replay stored trace; it never re-runs logic;
- corrupt current -> validate/load backup; corrupt both -> preserve evidence and offer fresh profile;
- unsupported future schema -> refuse destructive downgrade and preserve file;
- demo import is monotonic and idempotent; repeated/older import cannot duplicate achievements or reduce records;
- offline progress later meeting another device may merge monotonic completion/best records, but divergent active checkpoints are never silently merged;
- machine-local graphics settings stay out of cloud progression.

Phase 11 must include these as acceptance criteria, not implementation suggestions.

## 10. Reason-trace completeness
Every authoritative mutation requires a structured ReasonEvent. Collapsed UI may summarize, but expanded `What changed?` must include all persistent writes, bad writes, carrier hops, objective-relevant NOW changes and terminal cause. If two simultaneous events occur, stable trace ordering is presentation reproducibility only and never implies causal priority.

Golden cases must compare exact structured traces for LT01–LT06 and at least one late synthesis fixture.

## 13. Case 36 — two alternative proof structures
### Alternative A — Dependency Braid — ACCEPT
Sites: Garden, Bakery, Depot, Station, Bridge plus up to three support sites. Clocks 07:55/08:00/08:05 (or equivalent authored labels). One carrier.

Proof:
1. Garden must earn SAFE/COLLECTED before the dangerous productive footprint is ever used.
2. Bakery process must earn its persistent cargo milestone while the relevant clock is still free.
3. Cargo must dispatch/arrive before Station's acceptance/coupled event; arrival cannot accept in the same Resolve.
4. Once Garden and cargo are persistent, their clocks can be repurposed.
5. Final Resolve reserves 08:00 for Bridge and 08:05 for Station, triggering the coupled event and satisfying final NOW.

Why it is finale-worthy: hazard ordering, persistent freeing, carrier boundary and final simultaneity are interdependent, but the proof remains five claims. It is not merely Case 24 because carrier arrival changes the prerequisite DAG; it is not Case 34 because it uses one carrier and focuses on freeing clock roles rather than managing two transport channels.

### Alternative B — Double Hazard + Two Carriers — REJECT
Proof would be: secure two hazards, prepare two cargoes, move through two carriers, then create Bridge/Station coupled state.

Reject because it mostly scales Case 34 by adding more entities/boundaries. It increases execution and bookkeeping without a new causal relationship, risks >6 Resolves and duplicates the “secure hazard, stage carriers, reserve finale” proof.

### Backup structural direction if A fails playtest
Use a **choice-collapse finale**: two initially viable preparation orders remain open until one persistent milestone changes which footprint can safely serve the final coupled state. This is admissible only if the change is fully public and uses existing families. It must not introduce hidden branch rules or a bespoke exception.
