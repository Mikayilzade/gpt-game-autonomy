## Fresh market/analogue check
Fresh research on 2026-08-30 changed several risks materially:
- **Decommission Protocol** is a 2026 Steam title explicitly about decommissioning a derelict station. Its play is manual-elevator exploration plus floor-specific shutdown minigames/horror rather than systemic irreversible dependency removal, but the title/fantasy collision is now real. G7C01 can survive mechanically only under a different product identity/title and a clearly systemic shutdown verb.
- 2026 **Causal Loop** and **Echoed** both use recorded/replayed past actions. This raises derivative/readability risk for any Game #007 concept marketed mainly as temporal echoes/clones. G7C10 differs because rooms repeat actions one turn later rather than replaying a recorded avatar, but it must visibly foreground location-bound recurrence.
- Current programming-puzzle supply includes **Code, Solve, Revolt!** (2026) and **You Are The Code** (2025). G7C03 must remain direct physical delayed-command scheduling, not become drag-and-drop code construction.
- **Spectacle: Worlds Unseen** already uses blinking/visibility to alter surroundings, increasing the burden on G7C04 to prove that offscreen scheduling is more than a camera gimmick.
- Current premium puzzle competition also includes very high-content authored products, so Game #007 should compete through an ownable systemic verb and causal variety rather than raw puzzle count.

These are collision warnings, not evidence that the underlying mechanics are unusable.

# 1. G7C01 — DECOMMISSION

**30-second loop:** inspect a live dependency cluster -> choose one still-running subsystem -> preview what loses support / becomes independently safe or unsafe -> permanently retire it -> observe deterministic redistribution/fallback -> exploit the newly simplified but less capable facility -> choose the next removal.

**10-minute arc:** learn that shutdown is irreversible; discover dependency direction; learn that redundancy can be intentionally consumed; first puzzle where removing an apparently useful subsystem is necessary because its continued presence prevents safe retirement elsewhere.

**Hour-4 depth:** conditional dependencies, fallback modes, shared support, startup/shutdown asymmetry, residual stored state, irreversible order planning. Depth comes from subtractive state, not new minigames.

**Dominant-strategy threat:** always remove leaves/peripheral systems first. Counterexample requirement: mature cases where a leaf must remain to absorb/mediate a later transition and an internal subsystem must be retired earlier.

**Content burden:** medium-low if facilities are data-authored dependency machines; high if each subsystem becomes a bespoke minigame. Bespoke minigame direction is forbidden if selected.

**Technical/determinism:** strong. Discrete dependency state and atomic retire transitions are solver-friendly.

**Visual/demo:** good if power/flow/fallback is physical and visible; weak if presented as a node graph. A clip can show one removal causing several machines to change state.

**Accessibility/input:** strong; turn-based, previewable, no precision/timing required.

**Portfolio collision:** moderate with Tension Budget if it becomes resource redistribution, and Stitchspace if it becomes dependency-cut topology. Must focus on irreversible loss of capabilities and shutdown order, not network rewiring.

**Market risk:** high naming/fantasy collision with 2026 Decommission Protocol; mechanics remain differentiated.

**Kill condition:** kill if mature solutions reduce to reverse topological sort / remove-leaves-first with cosmetic exceptions.

**Verdict: SURVIVE, but title/fantasy must change before thesis lock.**

# 2. G7C02 — LAST KNOWN SHAPE

**30-second loop:** observe object under a chosen viewing condition -> move/occlude/leave -> manipulate scene so the object's authoritative remembered silhouette/state differs -> return or trigger interaction -> use the now-physical remembered form to bridge/block/fit/press -> revise observation when needed.

**10-minute arc:** observation freezes one simple shape; learn that direct re-observation overwrites it; discover that perspective/occlusion can change what counts as the observed shape; first puzzle where preserving an old observation matters more than seeing current reality.

**Hour-4 depth:** observation provenance, partial occlusion, multiple objects, ordering of re-observation, remembered affordances and controlled conflicts between current hidden geometry and last authoritative observation.

**Dominant-strategy threat:** find the largest/most useful silhouette once and keep it forever. Mature cases must require repeated overwrite and conflicting desired forms.

**Content burden:** medium-high. Requires carefully authored geometry and camera/view conditions, but small reusable object vocabulary could control scope.

**Technical/determinism:** medium. Exact definition of `observed shape` is dangerous; free camera/image-space interpretation would be brittle. Survivable only if observation states are authored/discrete rather than arbitrary computer vision.

**Visual/demo:** excellent. One of the strongest short-clip concepts if transformation is immediate and readable.

**Accessibility/input:** medium. Must avoid precision camera alignment; authored observation stations/frames are preferable.

**Portfolio collision:** low. Shape/state authority is new territory.

**Market risk:** moderate. Observation-changing-world games exist, but remembered shape becoming physical is distinct if discrete and legible.

**Kill condition:** kill if implementation requires pixel-perfect viewpoint hunting or if `what did the game think I saw?` cannot be predicted before commit.

**Verdict: SURVIVE.**

# 3. G7C03 — COMMAND LAG

**30-second loop:** inspect visible machine timelines -> issue one direct physical command -> command enters a fixed visible delay lane -> advance/act elsewhere -> multiple queued consequences mature in deterministic order -> exploit overlap -> cancel/replace only where explicit rules allow.

**10-minute arc:** one delayed door; two devices with different fixed delays; learn that present movement is itself part of scheduling; first puzzle where a command that looks premature is correct because another consequence matures first.

**Hour-4 depth:** heterogeneous fixed delays, dependency windows, commands whose future effects alter legal future commands, limited cancellation, synchronized machinery and planning under bounded horizon.

**Dominant-strategy threat:** queue everything immediately then wait. Mature fixtures must make later legality/state depend on earlier matured consequences and make premature commands harmful or invalid.

**Content burden:** low-medium. Reusable machines and timeline patterns can generate many authored cases.

**Technical/determinism:** excellent if turn/event based. Avoid real-time milliseconds.

**Visual/demo:** good, but timeline must not dominate the physical world. A clip can show three commands ripening in sequence.

**Accessibility/input:** strong with pause/step/undo and non-color timing identity.

**Portfolio collision:** low-medium; temporal scheduling is distinct from prior games.

**Market risk:** moderate. Programming/automation puzzle space is active; direct embodied commands and visible delayed execution must be the differentiator.

**Kill condition:** kill if optimal play becomes writing a static script before pressing Run, or if the physical scene is merely decoration around a programming UI.

**Verdict: SURVIVE — strongest systems candidate.**

# 4. G7C04 — OFFSCREEN SHIFT

**30-second loop:** frame scene -> deliberately hide a worker/machine -> perform/advance one deterministic step -> hidden actor executes its rule -> reveal to inspect result -> reframe to control which actors may advance next.

**10-minute arc:** one actor moves only unseen; two actors create selective activation; occluders let one act while another remains watched; first puzzle uses camera composition as a scheduling mask.

**Hour-4 depth:** nested occlusion, actor-specific offscreen rules, simultaneous hidden resolution, movable blockers/cameras, deliberate information sacrifice.

**Dominant-strategy threat:** flick camera away/back repeatedly until solved. Countering it tends to require action budgets or complex simultaneous state, which risks making the gimmick punitive.

**Content burden:** medium; camera-safe layouts and occlusion readability need substantial authoring/QA.

**Technical/determinism:** medium-high risk in 3D if actual frustum/occlusion decides authority. Discrete visibility zones could solve determinism but weaken the magical hook.

**Visual/demo:** exceptional in a clip, yet cause can be invisible by definition.

**Accessibility/input:** medium-low; camera motion and visual dependence create motion-sickness/low-vision burdens.

**Portfolio collision:** low.

**Market risk:** increased by visibility/blink-altered-world analogues and anomaly/observation saturation.

**Kill condition:** kill if optimal play is repetitive peek-away-peek-back or if deterministic visibility requires UI that destroys the fantasy.

**Verdict: ELIMINATE.** Great trailer gimmick, weaker multi-hour product.

# 5. G7C05 — SPARE PARTS CHOIR

**30-second loop:** inspect two machines -> remove a functional module from donor -> donor immediately loses/changes behavior -> physically install module in recipient -> use new behavior -> later transplant again as system state changes.

**10-minute arc:** one interchangeable module; donor consequence; module type interactions; first puzzle requires breaking a machine that initially looks essential.

**Hour-4 depth:** compatibility, persistent donor damage, machines whose behavior depends on missing combinations, module order, temporary repair chains.

**Dominant-strategy threat:** identify best machine and concentrate all useful modules there. Requires compatibility/physical constraints to resist, risking feature proliferation.

**Content burden:** medium-high due to readable modular machine art and animation.

**Technical/determinism:** strong with discrete sockets/modules.

**Visual/demo:** excellent.

**Accessibility/input:** strong if snap/socket interaction.

**Portfolio collision:** high with Borrowed Collision: take capability from A, A loses it, install/spend at B. Persistence is a distinction but the satisfaction loop is too similar.

**Market risk:** otherwise moderate.

**Kill condition:** portfolio collision alone is sufficient unless the experience ceases to be capability transplantation — which would remove the hook.

**Verdict: ELIMINATE.** Save as exclusion history, not future canon.

# 6. G7C06 — MUSEUM OF ALMOSTS

**30-second loop:** inspect 2–4 witness statements/depictions -> rotate/configure a physical artifact -> test one claim under its stated perspective/context -> contradiction feedback narrows possibilities -> revise until all claims coexist.

**10-minute arc:** literal spatial descriptions; viewpoint-relative statements; contextual qualifiers; first apparent contradiction resolved because witnesses saw different orientations/states.

**Hour-4 depth:** combinatorial testimony constraints, perspective, temporal ordering, partial reliability and artifact transformations.

**Dominant-strategy threat:** brute-force configurations against green/red validation. Must delay/globalize validation or make deductions cheaper than enumeration without becoming hostile.

**Content burden:** very high. Every case needs authored statements, localization QA and compatible artifact geometry.

**Technical/determinism:** strong mechanically, but localization is design-critical.

**Visual/demo:** medium. Artifact is attractive; reasoning often lives in text and is hard to trailer.

**Accessibility/input:** medium; language/cognitive burden high, though motor burden low.

**Portfolio collision:** medium with False Map Department because player reconciles representations/descriptions against physical truth.

**Market risk:** deduction niche can work, but content cost and portfolio overlap dominate.

**Kill condition:** kill if text authoring/localization is the primary scalability engine.

**Verdict: ELIMINATE.**

# 7. G7C07 — QUEUE COLLAPSE

**30-second loop:** inspect live queue and current service rule -> move exactly one job/person -> front item completes -> its completion changes one visible priority/service rule -> queue partially reorders/resolves -> make next intervention.

**10-minute arc:** one reorder; completion-triggered rule change; jobs with dependencies; first case where deliberately delaying an easy job prevents a bad rule transition.

**Hour-4 depth:** dynamic comparators, dependency classes, limited interventions, multi-stage jobs, queue mutations and local/global objectives.

**Dominant-strategy threat:** always move the currently blocking/highest-cost job. Rule changes can counter this, but risk opaque bookkeeping.

**Content burden:** low-medium if abstract; medium if each job needs character flavor to feel alive.

**Technical/determinism:** excellent.

**Visual/demo:** medium-low. Queue movement is readable but not spectacular; risks looking like UI optimization.

**Accessibility/input:** excellent.

**Portfolio collision:** medium with Organism Cargo/logistics and generic scheduling.

**Market risk:** weak emotional fantasy and spreadsheet impression.

**Kill condition:** kill if a screenshot looks like a queue-management tool rather than a game, or if flavor is required to carry the product.

**Verdict: ELIMINATE.** Mechanically respectable, commercially weaker than remaining field.

# 8. G7C08 — CHAIN OF CUSTODY

**30-second loop:** inspect object's visible custody marks -> choose who may handle/pass it next -> transfer physically -> handling appends/replaces a provenance fact -> doors/machines accept or reject based on exact history -> route actor/object accordingly.

**10-minute arc:** one permission by last handler; two-step provenance; forbidden handler; first puzzle where an apparently useless intermediary is necessary to establish valid history.

**Hour-4 depth:** bounded history predicates, sanitization/reset, mutually exclusive certifications, actor access differences, order-sensitive handoffs.

**Dominant-strategy threat:** route everything through a universal certifying actor. Must ensure no universal actor and make some handling invalidate other permissions.

**Content burden:** medium. Physical actors/stations can be reused; provenance UI must be excellent.

**Technical/determinism:** excellent if history is bounded symbolic state rather than unbounded event log.

**Visual/demo:** medium-good if object visibly accumulates stamps/seals; weak if permissions are text lists.

**Accessibility/input:** strong.

**Portfolio collision:** medium with cargo/logistics, but the core variable is history rather than destination/routing throughput.

**Market risk:** moderate; can read bureaucratic unless physicalized strongly.

**Kill condition:** kill if solving requires reading an ever-growing audit log or if provenance can be compressed to ordinary colored keys.

**Verdict: SURVIVE, conditional.**

# 9. G7C09 — UNDERSTUDY CONTROLS

**30-second loop:** select a physical control -> detach its authority from machine A -> bind to compatible machine B -> A immediately loses that verb, B gains it -> operate control -> reassign as consequences change.

**10-minute arc:** one switch controls one door; rebind; donor loss matters; later one control's semantic effect depends on recipient.

**Hour-4 depth:** scarce control vocabulary, recipient-specific semantics, simultaneous loss/gain, physical access to controls, sequencing.

**Dominant-strategy threat:** park each control on the globally best recipient. Needs changing state/access/compatibility.

**Content burden:** medium.

**Technical/determinism:** strong.

**Visual/demo:** excellent: cable/label/control visibly moves authority.

**Accessibility/input:** strong.

**Portfolio collision:** high with Borrowed Collision and also structurally resembles Stitchspace's scarce persistent endpoint replacement: reassign scarce relation, donor loses, recipient gains. Different noun, familiar causal skeleton.

**Market risk:** moderate.

**Kill condition:** if differentiation depends on theming rather than a different causal skeleton from #003/#006, kill.

**Verdict: ELIMINATE.**

# 10. G7C10 — RECURRENCE DEPARTMENT

**30-second loop:** enter/act in room A -> move elsewhere -> one turn later room A repeats the semantic action locally -> position yourself/objects so the recurrence helps rather than harms -> chain new room echoes while older ones resolve.

**10-minute arc:** one room repeats a button press; learn recurrence delay and local target mapping; two rooms overlap; first puzzle deliberately seeds an action now for a state that will exist next turn.

**Hour-4 depth:** overlapping location-bound recurrences, action classes, recurrence overwrite rules, object state changed between seed and replay, cancellation by revisiting, chains where an echo seeds another consequence.

**Dominant-strategy threat:** seed every useful room then wait. Mature states must make repeats persistent/mandatory enough that extra echoes create conflicts, while keeping the system understandable.

**Content burden:** low-medium. Reusable room/action vocabulary.

**Technical/determinism:** excellent as turn-based semantic replay.

**Visual/demo:** good if rooms visibly telegraph a one-turn `ghost action`; avoid clone avatars.

**Accessibility/input:** excellent with turn-based play, undo and redundant timeline cues.

**Portfolio collision:** low.

**Market risk:** temporal echo space is active in 2026 (Causal Loop, Echoed), but both emphasize recorded/replayed selves. Location-bound one-turn semantic recurrence remains differentiated if presentation never resembles clone recording.

**Kill condition:** kill if the most legible implementation becomes a ghost clone replay, or if players must track more than a small bounded set of pending recurrences mentally.

**Verdict: SURVIVE — high-interest.**
