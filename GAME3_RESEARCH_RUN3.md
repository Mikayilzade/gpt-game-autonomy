# 2. G3C30 — SINGLE-PIXEL KINGDOM

**10-second verb:** move one state-carrying pixel through an object/region, temporarily absorb one visible property, then touch another object/region to deposit that property.

**Pleasure:** a microscopic actor causes a macroscopic transformation; route choice and state choice are the same action.

**Muted clip:** one pixel touches a red solid block -> becomes red/solid carrier -> crosses ghost geometry -> touches a transparent bridge -> bridge becomes solid while donor loses or cools down its state.

**First 5 minutes:** move; absorb `SOLID`; transfer it to one ghost platform; then learn that carrying `HOT`, `HEAVY`, `RED` or `ALIVE` changes what can be crossed/touched. One deliberate wrong transfer is reversible and visually obvious.

**30m / 3h / 10h:** single property routes -> two-step state chains and temporary trails -> multi-room state logistics where route order matters, with at most 6–8 canonical property families.

**Dominant exploit:** carry one universally useful state, especially SOLID, everywhere.

**Boring strategy:** slow safe route planning with no expressive movement.

**Graybox:** 20×12 tile room; one pixel; SOLID/COLOR/HOT states; 8 objects; timed state decay optional; instant reset; 8 scenarios.

**Kill:** reject if after 6 scenarios >50% of solutions use the same carried state as the first move; if >25% of failures are caused by players not seeing current carried state; or if testers describe it as a generic dot platformer rather than state transfer.

**<=8-rule proof:** carrier state, donor state, receiver compatibility, temporary trail, hazards, gates, moving carriers, state decay. These can generate traversal, ordering, rescue, exclusion, relay, chase, timing, multi-room and minimal-transfer situations well beyond 20 without a new property every level.

**Comparison:** `Adventures of Pip` owns one-pixel protagonist imagery but uses evolution/form changes, not property transport.

**Big subsystem:** content validation/readability, not art.

**Accessibility:** generous grid/focus movement, speed options, redundant icon/pattern state display, no color-only identity.

**Theme stripped:** strong; the abstract state-carrier loop survives.

**Portfolio:** very high independence; neither logistics planning nor ontological map editing.

**Decision: ADVANCE STRONGLY.**

# 3. G3C12 — BUREAU OF LOST WEIGHT

**10-second verb:** detach a visible mass certificate from one object and attach it to another; total certified mass remains conserved and both objects immediately behave differently.

**Pleasure:** every solution creates a collateral physical tradeoff; making one object useful necessarily changes another.

**Muted clip:** 100 kg safe becomes light enough to float while a balloon receiving the certificate crashes through a floor.

**First 5 minutes:** transfer 10 kg from crate to platform; use lighter crate; discover heavier platform now compresses a switch; then first tradeoff where dumping all mass onto one anchor causes structural failure.

**30m / 3h / 10h:** simple lift/buoyancy -> inertia/pressure/support interactions -> multi-object mass economy with transport, momentum, load-bearing and temporary custody.

**Dominant exploit:** dump all surplus mass into an irrelevant anchored object.

**Boring strategy:** repeatedly test every legal certificate placement.

**Graybox:** deterministic 2D rigid-body-like graph physics rather than free chaotic physics; 5 objects, 3 certificates, buoyancy/support/inertia rules, 8 scenarios.

**Kill:** reject if one sink object is optimal in >40% of mature scenarios; if deterministic simplified physics feels arbitrary to >2/5 testers; or if exact collision timing is required for ordinary completion.

**<=8-rule proof:** conserved mass, support capacity, buoyancy, inertia, pressure switches, transport capacity, break threshold, momentum response. >=20 scenario families follow directly.

**Comparison:** `The GoD Unit` and other physics puzzlers manipulate mass, so generic weight-changing is not the pitch. Conservation transfer is the only defensible center.

**Big subsystem:** deterministic physics/state QA.

**Accessibility:** no precision throwing required; snapped transfers; pause/step for moving interactions; numeric kg values paired with visual size/weight feedback.

**Theme stripped:** strong conservation puzzle.

**Portfolio:** high independence.

**Decision: ADVANCE STRONGLY.**

# 4. G3C15 — BORROWED COLLISION

**Comparison:** trajectory and inertia games exist, but fresh search still did not find a primary loop built around portable resolved collision outcomes.

**Big subsystem:** deterministic collision quantization and UX explanation.

**Accessibility:** snap directions, pause/slow mode, no mandatory twitch timing, iconized strength bands.

**Theme stripped:** very strong.
