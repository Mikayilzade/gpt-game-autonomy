## Equal destructive Round A

### A — WRONG ADDRESS
- Stranger comprehension: GOOD. “Hide parts of one address so different machines read different destinations” is explainable, but needs a diagram to make shared-reader effects obvious.
- First 10 minutes: reveal parcel fields -> introduce one reader -> one cover -> two readers with different field priority -> first shared intervention affecting several parcels. Strong tutorial economy.
- Hour 3 / 10: reader predicates, shared stencils, batches and ordering can create variety, but the interaction remains mostly inspect/cover/run. Risk of increasingly dense bookkeeping rather than new reasoning.
- Vocabulary: small and validator-friendly: parcel descriptors, visible fields, reader predicate/order, stencil/occluder, route result.
- Brute force: finite but dangerous if preview/run is free. Needs attempt cost or informative-but-not-oracular preview; that would complicate an otherwise clean design.
- Content burden: moderate. Validator can enumerate states, but authored readability is harder than solvability.
- Controller/Deck: good if fields are large; text density and localization are real burdens.
- Trailer: medium. Routing divergence is visible, but why it happened may not read in a silent GIF.
- Boredom mechanism: spreadsheet drift and repeated predicate checking.
- Derivative/portfolio: sufficiently distinct mechanically, though bureaucratic/parcel skin weakens catalog distinctness.
- Verdict: KILL. Cheap to build is not enough; weak audiovisual proof and hour-10 interaction diversity are structural.

### B — COUNTERWEIGHT OFFICE
- Stranger comprehension: EXCELLENT. “Move one weight and the whole hanging organization rebalances.”
- First 10 minutes: one lever -> unequal weights -> nested mobile -> height/clearance target -> first distant coupled consequence. The player learns by motion rather than text.
- Hour 3 / 10: distinct decisions can include object-to-hook assignment, discrete hook radius, nested branch coupling, clearance/order bands, fixed/limited movable nodes, and optional ballast. Depth comes from hierarchy, not more verbs.
- Vocabulary: mobile node, arm, discrete hook slot, mass class, equilibrium orientation/height, clearance/target band. Keep masses as visual unit tokens and lever arms as discrete notches; never ask player to calculate torque numerically.
- Brute force: enumerable, but branching can grow. Validator can prove solutions/minimum moves; UI must not expose exhaustive auto-preview.
- Content burden: good. Small graph-like level data, solver-assisted generation/mutation plausible. Need handcrafted composition for visual legibility.
- Controller/Deck: strong if hooks snap and target bands are large. Entire puzzle can fit one screen with pan/zoom only for larger mastery cases.
- Trailer: excellent. One drag -> cascading deterministic settle -> several target bands turn valid.
- Demo: 20–30 minutes can introduce nesting and finish on a three-branch coupled puzzle without requiring story.
- Technical risk: moderate. Do NOT use free continuous physics as authority; calculate deterministic discrete equilibrium and animate toward it.
- Boredom mechanism: if every problem is “balance to horizontal,” it becomes algebra. Survival requires multiple spatial predicates (clearance, relative height, forbidden crossing/zone, branch tilt bounds) all derived from the same equilibrium state.
- Derivative/portfolio: strong new physical identity; office fiction is dispensable and should not become bureaucracy canon.
- Verdict: FINALIST.

### C — PROOFREADER'S CUT
- Stranger comprehension: GOOD verbally, mediocre visually.
- First 10 minutes: insert one blank -> downstream shift -> fixed windows -> heterogeneous token rules. Extremely clean.
- Hour 3 / 10: can add blank budgets, window widths, modulo/alignment predicates and locked regions, but most decisions remain insertion positions along one dimension.
- Vocabulary: tiny; solver and uniqueness checking excellent.
- Brute force: severe. With n gaps and k blanks the state space is easy for a player to enumerate unless instances become long, which directly worsens readability.
- Content burden: technically low, design burden high because difficulty tends to come from longer strings.
- Controller/Deck: excellent mechanically, poor for dense symbols on small display.
- Trailer: weak. A blank shifting characters is understandable but not exciting.
- Boredom mechanism: scan candidate gaps, test, repeat.
- Verdict: KILL. Elegant puzzle-paper mechanic, weak videogame product and weak resistance to enumeration.

### D — TIDE TABLE
- Stranger comprehension: EXCELLENT. “Choose the tide; the harbor moves globally and cargo can transfer only when things line up.”
- First 10 minutes: tide slider with one boat/dock -> two heights -> cargo transfer -> tether/bridge constraint -> first transfer that changes what must align later.
- Hour 3 / 10: potential decision families: next global level, which transfer to take at that level, cargo-induced draft/height changes, movable ballast/cargo distribution, limited tide changes, tether range, bridge clearance, boat-to-boat transfer. This is enough only if cargo changes future geometry; otherwise it is a timetable.
- Vocabulary: water level, hull/draft class, dock interface height, tether range, cargo mass/slot, transfer, clearance. Avoid continuous buoyancy math; all heights and draft deltas are discrete public units.
- Brute force: finite sequence search. Danger rises if only 3–5 tide values; depth must come from irreversible/limited transfers and state-dependent draft, not longer sequences.
- Content burden: good if represented as discrete harbor graph + height tables. Solver can validate reachability and shortest tide-change counts.
- Controller/Deck: strong. Tide selection and cargo transfer are simple; side-view harbor gives persistent visual state.
- Trailer: excellent: one global water-level change moves every hull, changes bridge/tether states and exposes a transfer opportunity.
- Demo: exceptionally clean stopping point: final demo puzzle requires loading cargo onto one boat to change its draft so a later shared tide aligns a different transfer.
- Technical/art risk: moderate. Water is presentation only; authoritative simulation is discrete. Needs strong interpolation/rope animation but no fluid sim.
- Boredom mechanism: “set level X, move crate, set level Y.” Countermeasure must be a compact but rich draft/transfer architecture, not arbitrary hazards.
- Derivative/portfolio: distinct from #018 if tide is a single global environmental variable and no movable semantic zones/milestones exist. Must prohibit Local-Time-like region logic.
- Verdict: FINALIST / current leader, conditional on semifinal proof that cargo mass changes future alignment in intuitive ways.

### E — LOST CARBON
- Stranger comprehension: HIGH once carbon paper is understood; generational familiarity is a concern.
- First 10 minutes: one strike through two sheets -> backing blocker -> reorder -> cutout -> exact per-layer marks.
- Hour 3 / 10: layer order, transmission depth, strike reuse, cutout geometry and multiple marks provide combinatorics but the fundamental action stays stack/strike/reveal.
- Vocabulary: compact and solvable.
- Brute force: manageable for validator, but player trial-and-error can become cheap unless strikes are committed; irreversible strikes then increase reset friction.
- Content burden: moderate, mostly pattern authoring.
- Controller/Deck: good; exploded-stack view is necessary.
- Trailer: good reveal, less clear planning.
- Boredom mechanism: repeatedly inspect transmission columns.
- Portfolio: simultaneous transmission is technically distinct, but stack + blocking + persistent marks sits uncomfortably near prior paper/masking identities.
- Verdict: KILL on portfolio distinctness plus limited long-tail interaction diversity.

### F — SWITCHBOARD ETIQUETTE
- Stranger comprehension: excellent physical metaphor.
- First 10 minutes: cord pair -> lamp/ring -> shared circuit -> forbidden signaling state. Tactile onboarding strong.
- Hour 3 / 10: circuits, cord scarcity and sequencing could work, but conventional graph-routing pressure remains.
- Vocabulary: moderate; historically inspired switchboard keys/lamps/cord circuits support signaling interactions.
- Brute force: finite and validator-friendly.
- Controller/Deck: cord dragging can be good but cable occlusion is a small-screen risk.
- Trailer: tactile and audible.
- Contemporary collision: FAIL. Multiple switchboard-operator games are visible now, including a Steam historical puzzle/adventure released April 2026 and current cable-routing/connection titles on Playdate/mobile. Even if etiquette predicates differ, screenshots and store capsule would read as the same crowded object fantasy.
- Boredom mechanism: connection bookkeeping.
- Verdict: KILL HARD. Market-surface collision overwhelms mechanical nuance.

### L — RETURN TO SENDER
- Stranger comprehension: VERY GOOD in motion: capsule orientation is memory carried through transparent tubes.
- First 10 minutes: notch reader -> fixed rotate station -> branch by orientation -> configure one station -> launch batch.
- Hour 3 / 10: orientation group/state, fixed transforms, shared station settings, batches and merges can create real depth. But route planning and launch/revise loop remain close to machine-routing puzzles.
- Vocabulary: capsule orientation, sensor, transform, branch, station setting, route.
- Brute force: configuration search can be solved exhaustively unless settings interact across several capsules; batch coupling helps.
- Content burden: good; deterministic graph solver straightforward.
- Controller/Deck: excellent, transparent tubes visually strong.
- Trailer: excellent causal cascade.
- Boredom mechanism: configure -> simulate -> inspect can become an oracle loop; needs prediction tools that paradoxically make brute force easier.
- Portfolio: orientation-carried state is new, but routing/sorting presentation collides with #010 and factory history more than B/D/M.
- Verdict: SEMIFINAL RESERVE, not top-two. Keep only if B or D fails deeper proof.

### M — RECEIPT TEAR
- Stranger comprehension: HIGH. Tear a receipt and overlap pieces to expose valid coupon edge codes.
- First 10 minutes: scanner predicate -> one reversible overlap -> first irreversible tear -> two-strip recombination.
- Hour 3 / 10: tear partition, strip orientation, overlap offset, edge exposure, multiple coupon allocation. Still fundamentally a 1D substring/occlusion problem.
- Vocabulary: tiny and validator-friendly.
- Brute force: high; tear positions × offsets are easily enumerable unless receipt becomes long/dense.
- Content burden: low but risks puzzle-book feel.
- Controller/Deck: excellent.
- Trailer: satisfying tear, weak systemic spectacle.
- Boredom mechanism: slide until scanner turns green unless feedback is withheld; withholding makes it tedious.
- Portfolio: occlusion/physical-paper adjacency remains undesirable.
- Verdict: KILL.

## Semifinal: concrete loop proof

### D — representative problem families
D1 ALIGNMENT: choose tide so one hull meets a dock; teaches global level.
D2 SHARED LEVEL: two hulls with different drafts create mutually exclusive opportunities at the same tide.
D3 LOAD-CHANGES-DRAFT: transfer a heavy crate; loaded hull sits exactly one public height unit lower from then on. The transfer therefore changes later alignments.
D4 BALLAST CHOICE: a boat has two cargo slots/classes; carrying useful cargo versus ballast changes its future interface height.
D5 TETHER WINDOW: a hull may operate only inside a finite tide band because its tether reaches/slack/taut limits; this constrains sequence without hidden physics.
D6 BRIDGE CLEARANCE: high tide raises a mast/hull package into a blocked clearance state, making some horizontal transfer/route unavailable.
D7 BOAT-TO-BOAT RELAY: two boats can exchange only when their current interface heights match; changing one boat's load changes future rendezvous tides.
D8 LIMITED CYCLES: solve within a public number of tide changes; optimization arrives only after causal understanding.

Concrete core loop: inspect target cargo destinations and public height tables -> choose one of a small discrete tide levels -> all hulls deterministically move -> newly legal transfer interfaces highlight -> optionally transfer one/more cargo units -> cargo mass updates affected hull draft -> repeat until delivery predicates are satisfied. Crucially, the player is not programming a sequence blindly; each transfer changes later global-level consequences.

Semifinal proof: D survives the “mere scheduling” attack if and only if cargo mass/draft coupling is mandatory from the early game and remains bounded/readable (recommended base rule: each heavy unit changes a hull's interface height by exactly one level, with explicit capacity and no continuous weight arithmetic). Tethers/bridges are secondary constraints, not separate simulation systems.

### B — representative problem families
B1 SINGLE LEVER: place unit weights on discrete hooks to enter a target tilt band.
B2 NESTED EFFECT: changing a child arm alters its own tilt and the load presented to a parent, producing a visible hierarchy consequence.
B3 CLEARANCE: a hanging object must end above/below a public line while the arm remains within a tilt band.
B4 RELATIVE ORDER: two documents/trays must finish in a vertical order without requiring exact pixel heights.
B5 FIXED LOAD: some weights cannot move; choose leverage for the movable pieces.
B6 SHARED OBJECT CHOICE: limited ballast objects must be allocated among branches.
B7 MULTI-BAND: satisfy parent and child tilt/clearance predicates simultaneously.
B8 MOVE BUDGET: optional mastery asks for fewer relocations after a valid solution exists.

Concrete core loop: inspect target bands -> drag a weight/tray to a discrete hook -> deterministic solver computes exact arm angles/heights -> mobile animates to authoritative state -> check spatial predicates -> repeat. No free-body physics, velocities, collisions or numerical torque UI.

Semifinal proof: B can avoid arithmetic only if every mass and arm distance is encoded as tiny visual units/notches and valid target bands tolerate ranges. However, nested equilibrium still requires players to infer multiplicative lever effects. As levels grow, visual causality can become harder to parse than D's single shared tide axis. It remains a strong concept, but its readability ceiling is lower and implementation needs a robust layout solver to avoid arm/cord overlap.

### L — reserve proof
Representative families can use orientation transforms, branch sensors, shared station modes, capsule batches and merge conflicts. This is mechanically sound and validator-friendly, but the player's main cognition remains network tracing plus state transformation. It does not beat D/B on portfolio novelty and risks an oracle-like launch/revise loop. Reserve is therefore released.

## Semifinal decision
**D TIDE TABLE wins Phase 2 provisionally.** It has the clearest shared-variable causality, strongest silent-GIF proof, easiest controller mapping, and a credible route from tutorial to deep puzzles without adding verbs. B remains the sole runner-up and is intentionally preserved here as rejected tournament history, not canon.

Phase 3 should lock D only after formalizing the anti-shallow product thesis around these invariants:
- one global discrete tide level affects every floating object;
- cargo transfer can change a hull's future interface height through a tiny discrete draft rule;
- player agency is tide choice + legal cargo transfer, not direct boat steering;
- tethers/clearances constrain the same height state rather than becoming independent minigames;
- no continuous fluid/rope/rigid-body simulation is gameplay authority;
- no Local-Time-style movable zones, clocks, milestones or semantic-region logic;
- demo must prove load-changes-draft and boat-to-boat relay, not stop at simple dock alignment.
